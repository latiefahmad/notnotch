Version 1.1.1 fixes the updater. 1.0.0 and 1.1.0 were signed with a different key than the one they ship, so every update download was refused as unverifiable and the app stayed on its old version.

## What changed

- **Updates install again.** This release is signed with the key the app trusts. Copies of 1.0.0 and 1.1.0 cannot install it by themselves, because they only trust the old key: install 1.1.1 once by hand with the installer below. From 1.1.1 on, the in-app update works.
- **The release workflow checks the key.** Before a release becomes the latest one, every signature in `latest.json` is compared with the public key in `tauri.conf.json`. A mismatch stops the run while the release is still a prerelease, so a release every installed copy would reject is never offered.
- **Publisher.** Control Panel and Apps & features list the publisher as `latiefahmad` instead of `github`, which Tauri takes from the second part of the identifier when no publisher is set.
- **Copy diagnostics** now says `update signature` when a download fails its signature check, instead of the blanket `update check-failed`.

## Under the hood

- `scripts/verify-signing-key.mjs` compares the minisign key ids and runs in the `checksums` job before `gh release edit --latest`.
- The update store keeps why an attempt failed (the check itself, the download and install, or the signature), and the release workflow no longer depends on a password secret: the signing key has none.
